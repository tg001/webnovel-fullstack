# AI 协作创作工作流：人机分工、上下文工程与交付流水线

> 解决核心问题：**怎么用 AI 写完几十万到上百万字长篇，而不在十万字处崩盘。** 01-09 是"写作方法论"（图纸），本文档是"生产方式"（施工队怎么分工）。
> **配套**：三张表模板见 `12-project-scaffold.md`；可直接复制的提示词见 `11-prompt-library.md`；AI通病诊断依据见 `06b-ai-diagnosis.md`。

---

## 第一部分：核心认知

### 一、AI 能做什么，不能做什么

| 任务 | 可交给 AI | 需人工主导 | 原因 |
|------|:--------:|:---------:|------|
| 拆书分析 | ✅ | | 单点任务，输入输出闭环 |
| 单章正文初稿 | ✅ | | 有细纲约束时质量可用 |
| 去AI味改写 | ✅ | | 规则明确，可批量 |
| 合规初筛 | ✅ | | 清单化，机械比对 |
| 章节摘要生成 | ✅ | | 事后归纳，风险低 |
| 单章细纲 | ✅ | 复核 | AI 易在"转"环节插入无关支线 |
| **全书大纲** | | ✅ | AI 会把"合"压缩成一句话 |
| **卷级结构+支线规划** | | ✅ | AI 天然不写支线（仙人球结构）|
| **伏笔埋设与回收** | | ✅ | 跨几十万字记忆，AI 必忘 |
| **人物弧光+关系变化** | | ✅ | 需要判断"转变是否合理" |
| **一致性验收** | | ✅ | 不能信 AI 的记忆，必须人工比对事实库 |
| **文风定调/最终取舍** | | ✅ | 审美和作者意志无法外包 |

**一句话原则：人类负责"地图和图纸"，AI 负责"砌砖"，而不是让 AI 自己盖楼。**

### 二、人机分工模型（四个角色）

```
① 架构师（人）——大纲、卷结构、支线、伏笔、文风基调 → 输出：全书大纲/卷级大纲/人物库/伏笔表
② 施工员（AI）——按细纲出正文初稿，按规则局部改写扩写 → 输出：原文/第N章.md
③ 质检员（AI 初筛+人终审）——合规扫描、AI味扫描、一致性比对 → 输出：问题清单
④ 作者（人）——修改、定稿、沉淀风格画像 → 输出：改文库/第N章.md（权威版本）
```

**关键纪律**：
- **改文 = 权威**。后续章节的上下文只以改文库为准；AI 初稿（原文/）不得作为后续创作依据（详见 `06a` 第五部分）。
- **AI 不做未经复核的跨章承诺**。AI 在某章写下的新设定、新伏笔，必须在同一轮里登记进维护文档，否则下一章必丢。

## 第二部分：上下文工程

### 一、为什么必须做

根因（见 `06b` 第五轮）：上下文窗口有限，AI 只能看到最近的内容，前面十几万字的设定会"滚出视野"，然后 AI 会"发明"一个合理但错误的替代（第1章蓝眼睛古剑 → 第4章棕眼睛激光枪）。**不要相信 AI 的记忆，由人提供记忆。**

### 二、三层骨架（让 AI 随时知道"我们在哪"）

| 层级 | 内容 | 更新频率 |
|------|------|---------|
| 主线一句话 | 这本书讲什么（**因果链形式，不是主题词**） | 立项时定，极少改 |
| 每卷三句话 | 本卷开端状态 / 核心冲突 / 卷末状态 | 每卷开写前定 |
| 每章一句话 | 本章推进了什么、改变了什么 | 每章写前定 |

- ✅ 正确示范："因为主角要替被灭门的师门讨回公道（因），所以必须以假身份混入仇家宗门往上爬（果），而每往上一步就离'自己也可能成为仇家那种人'更近一步（冲突）。"
- ❌ 反例："本书讲述了主角在修仙世界不断变强、最终成为强者的故事。"（主题词，无法约束具体章节）

### 三、三张表（让 AI 随时能查"事实"）

| 表 | 记录什么 | 更新时机 |
|----|---------|---------|
| **人物库** | 每个有名字角色的外貌/性格核心/能力等级/**当前状态**/关系/弧光进度 | 每章写完后 |
| **伏笔表** | 伏笔内容/埋设章/类型/计划回收章/状态（未回收/已回收/已废弃） | 埋或收时 |
| **时间线表** | 关键事件/发生时间/涉及人物年龄/季节 | 每章写完后 |

> 空白模板见 `12-project-scaffold.md`。字数少于 30 万字的作品可只维护"人物库+章节摘要"两张，伏笔和时间线记在摘要里。

### 四、提取 → 注入 → 验证（三层层锁，每章走一遍）

**① 提取——写完就登记**：从新章正文提取所有故事关键信息——新出场人物（外貌/性格/能力）、人物状态变化（受伤/晋级/关系转变）、新设定（世界观细节/能力规则）、新埋伏笔和回收的旧伏笔、时间推进（过了几天/季节）。

**② 注入——写前才给料**：写新章时固定喂给 AI 五样东西：
```
1. 上一章结尾原文（500-800字）
2. 当前卷三句话骨架
3. 本章出场角色的当前状态（从人物库摘）
4. 未回收伏笔清单（只列与本章相关的）
5. 本章涉及的设定条目（从世界观摘）
```

**③ 验证——写后必比对**：新章节与事实库逐条比对，标记矛盾。重点查：人物名字/外貌/能力等级一致？有没有"角色突然知道不该知道的事"？伤势有没有"上章重伤这章痊愈"？上章钩子接住了吗？时间有没有凭空跳跃？

> **审计节奏**：每 5 章小审计（人物/关系/物品/伏笔），每卷末大审计（设定/时间线/关系/伏笔全覆盖）。

### 五、单章上下文注入模板（可直接复制）

```
【上下文】写第 N 章前请先读以下材料，严格遵守，不得自行发明新设定。

一、全书主线（一句话）
<粘贴>
二、当前卷骨架（三句话：开端状态 / 核心冲突 / 卷末状态）
<粘贴>
三、上一章结尾
<粘贴最近 500-800 字原文，或改文库版本>
四、本章出场角色当前状态
- <角色A>：<外貌特征要点> / <当前能力等级> / <当前情绪与处境> / <与主角当前关系>
五、本章相关未回收伏笔
- 伏笔1：<内容> —— 埋于第X章，计划在第Y章回收（本章是否需要提醒/回收？）
六、本章涉及的设定
- <核心规则条目> / <地理/势力/物品条目>
七、本章细纲
<粘贴细纲>

【写作要求】
- 视角人物：<X>，全程锁定，不跳视角
- 目标字数：<N>（2200-2800 区间）
- 本章节奏：开头<快/中/慢> → 中间<…> → 结尾<…>
- 章末钩子：<具体写出>
- 文风：<主文风 + 辅助元素>
- 禁止：情绪标签（他感到/他觉得）、"非常/十分/极其"、模板化过渡词、结尾升华句、旁白解释设定
```

## 第三部分：单章写作 SOP

### 一、写作前（人做，约 10 分钟）

- [ ] 读本章出场角色的当前状态（人物库）
- [ ] 读最近 3-5 章摘要（不是全文）
- [ ] 确认本章在卷骨架中的位置（推进了哪一步）
- [ ] 检查未回收伏笔清单：本章要不要提醒/回收？
- [ ] 写/复核本章细纲（用 `08` 模板5）
- [ ] 明确本章"最让我激动的地方"是什么（过不了这道闸门就别动笔，见 `06a` 第四部分）

### 二、写作中（AI 出初稿，人监控）

- [ ] 用"单章上下文注入模板"组织提示词
- [ ] AI 一次性出全章初稿，**不要边写边改**
- [ ] 人只做一件事：盯住"这一章有没有我觉得假的地方"——记下位置，不改
- [ ] 初稿存入 `原文/第N章.md`

### 三、写作后（质检+人工定稿，约 15 分钟，不要跳步）

1. **合规快检**（5分钟）：过 `02` 第二部分合规清单
2. **AI 味扫描**（3分钟）：用 `06b` 的 7 Gate 标记问题位置（A禁用词/B句式套路/C心理告知/D节奏均匀/E对话腔调/F结尾升华/G解释腔）
3. **一致性验证**（5分钟）：逐条比对人物库/伏笔表，标记矛盾
4. **人工修改定稿**：存入 `改文库/第N章.md`（权威版本）
5. **回写维护文档**：更新人物库、伏笔表、时间线、章节摘要
6. **（可选）触发风格学习**：改得多就跑一次"对比学习"（`11` I2），把差异归纳成风格规则

> **顺序很重要**：先改对，再改味。合规和一致性问题改不完，去AI味就是白做工。

## 第四部分：各阶段 AI 分工建议

| 阶段 | AI 承担 | 人承担 |
|------|--------|--------|
| 拆书 | 三层拆解、生成报告 | 判断"哪些技法可迁移到我的书" |
| 定位 | 提供选项、压力测试 | 拍板核心定位五问 |
| 世界观 | 展开七层细节、检查自洽性 | 定核心规则（≤3条）与代价 |
| 人设 | 生成小传初稿、备选活人感细节 | 挑选、把关"缺陷是不是真缺陷" |
| 大纲 | 生成备选、检查节奏分布 | **自己写主线和支线**，AI 只做校验 |
| 细纲 | 按模板出细纲、检查钩子密度 | 复核"转"环节有无塞无关支线 |
| 正文 | 出初稿、扩写、局部重写 | 改稿、定稿、沉淀风格 |
| 审核 | 合规扫描、AI味扫描、一致性初筛 | 终审 + 决定改不改 |
| 运营 | 生成书名/简介备选、标签建议 | 选型、对接平台 |

**三个最容易翻车的地方**：①让 AI 写大纲→主线变事件罗列，支线消失；②让 AI 记住伏笔→十有八九会忘；③让 AI 自己验收一致性→AI 会"记得"自己发明的错误版本。

### 分层模型协作（参考oh-story：不同模型干不同层级的活）

> **核心理念**：写小说也有架构师和搬砖工的区别——让最强的模型干最需要深度思考的活，让最快的模型干机械性检查活。Opus干Haiku的活是浪费钱，Haiku干Opus的活是出烂活。

| 层级 | 任务类型 | 推荐模型档位 | 原因 |
|------|---------|------------|------|
| **架构层** | 题材选择、全书大纲、卷级结构、钩子设计、反转布局 | 最强模型（如Claude Opus/GPT-4o） | 需要深度思考和全局视野，错了全书崩 |
| **创作层** | 角色设计、正文写作、场景描写、对话创作 | 中等模型（如Claude Sonnet/GPT-4o-mini） | 需要创造力和文笔，成本适中 |
| **检查层** | 一致性检查、AI味扫描、合规扫描、字数统计 | 最快模型（如Claude Haiku/轻量模型） | 机械性任务，速度快成本低，可以频繁跑 |
| **检索层** | 查资料、加载上下文、拆文分析 | 中等或最快模型 | 信息整理，不需要创造力 |

**协作流程示例**：
1. **架构层（最强模型）**：确定题材、写全书大纲、设计卷级结构和核心钩子
2. **创作层（中等模型）**：根据大纲写角色卡、写章节正文、创作场景和对话
3. **检查层（最快模型）**：每章写完后跑一致性检查、AI味扫描、合规扫描
4. **人**：终审、定稿、决定改不改

**为什么要分层**：
- 成本控制：最强模型贵，不要用它做机械性检查
- 质量保证：检查层用最快模型可以频繁跑（每章都跑），不会因为成本而跳过
- 效率提升：不同模型并行工作，架构层规划下一卷时，创作层在写当前卷，检查层在审上一章

**注意**：如果你只有一个模型（比如只用豆包），就用"提示词分层"代替——架构任务用"深度思考"提示词，检查任务用"快速扫描"提示词。

## 第五部分：去AI味四轮流水线

AI 初稿不要试图一次改到位。按四轮走，每轮只解决一类问题（提示词见 `11` F组）。

**第一轮：去痕（拆结构）**——打散机械句式；删除"首先/其次/最后""此外/与此同时/值得一提的是"；删除空洞强调词（非常/十分/极其/深刻/显著）；打破总分总和均匀段落；**删除所有结尾升华句**。

**第二轮：节奏（改呼吸）**——长短句交错，单句≤20字；紧张/动作→短句（5-10字）；抒情/慢→长句（15-25字）；关键情绪点→极短句（2-5字）独立成段；禁止连续3句长度相近。

**第三轮：人味（加质感）**——加具体感官细节（什么声音/什么气味）；加具体数字和时间（"走了很久"→"走了约一炷香"）；加生活细节和"无关紧要"的小事；加主观视角与偏见；角色会犹豫、说错话、犯小错。

**第四轮：通读（编辑验收）**——以资深编辑眼光通读，仍有AI味的地方直接改；重点看 7 Gate 哪几类有残留。**判定**：4个以上Gate有问题→重度；2-3个→中度；0-1个→轻度。

### 去味保护红线（权威源·不可越过）

去AI味是改"怎么说"，不是改"说什么"：

1. **不得整段删除正文内容**——多处AI味应逐句修改而非删整段
2. **删除前确认**：被删内容里有没有伏笔、钩子、角色特征、情节推进？
3. **删除比例上限**：轻度≤15%，中度≤25%，重度≤35%
4. **破坏连贯性时**：改为"降AI重写"而不是删除
5. **疑似但不确定**：标注 `[需复核]`，不要直接改也不要删
6. **保留作者意图**：只改"怎么说"，不改"说什么"
7. **保留有功能的标点**：质问的「？」、爆发的少量「！」可以留

## 第六部分：AI 协作常见失败模式与对策

| 失败表现 | 根因 | 对策 |
|---------|------|------|
| 写到十几万字开始前后矛盾 | 上下文窗口限制，设定滚出视野 | 上下文工程（三层骨架+三张表+注入模板）|
| 每章单看都行，整体像流水账 | 仙人球结构——没有支线 | 人主导设计支线，每5-10章一条 |
| AI 越写越像说明文 | 默认"受过教育的成年人"声音+旁白解释 | 角色声音卡；删旁白解释；对话加废话和打断 |
| 高潮很短，结尾一句话收尾 | "合"环节被压缩 | 人工扩写高潮；结尾加余韵 |
| 主角被动，被事件推着走 | AI 倾向"安全写作" | 每章问"主角这章主动做了什么选择" |
| 伏笔埋了就忘 | 无外置记忆 | 伏笔表+每卷末检查未回收项 |
| 越改越像 AI 味更重 | 一次改太多维度改崩了 | 严格按四轮流水线，一轮一类问题 |
| 改完之后剧情变了 | 去味时删掉了有功能的句子 | 遵守去味保护红线，先确认后删除 |

## 第七部分：开工前自检清单

**准备阶段**：三层骨架写好？三张表建立？目录结构初始化（见 `12`）？主文风+辅助元素确定（不是四种混用）？
**每章循环**：写作前读了角色状态+最近摘要+未回收伏笔？写作中用了注入模板、AI一次出完？写作后合规→AI味→一致性→人工定稿→回写维护文档？改文进改文库、原文留原文目录，不混用？
**定期**：每5章小审计？每卷大审计+卷级复盘？每5-10章文风自检？完本全书终审+伏笔全闭环？
**心态**：接受"AI 是施工队不是作者"；接受"第一本大概率扑街"——重要的是走完一遍全流程。
