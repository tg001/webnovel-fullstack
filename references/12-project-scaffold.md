# 项目脚手架：目录结构、维护文档模板与读写纪律

> 本文档解决"AI 写到十万字就崩"的**工程侧**问题——把 `10-ai-workflow.md` 讲的"三层骨架+三张表"落地成可以直接复制粘贴的空白模板和强制读写纪律。
>
> **适用判断**：30 万字以下可以只维护「人物库 + 章节摘要」两张；30 万字以上五张全开；百万字长篇建议再加一份"分卷设定变更日志"。

---

## 第一部分：目录结构

新建小说项目时，按此结构建目录：

```
<小说名>/
├── 小说资料/                    # ★ 维护文档区（AI 写正文前必读）
│   ├── 人物库.md
│   ├── 世界观.md
│   ├── 章节摘要.md
│   ├── 伏笔追踪表.md
│   └── 时间线表.md
├── 大纲/
│   ├── 全书大纲.md              # 主线一句话 + 卷级划分
│   ├── 卷级大纲.md              # 每卷三句话 + 关键节点 + 爽点规划
│   └── 章节细纲.md              # 每章一句话 + 详细细纲（可拆分为 章节细纲/ 目录）
├── 原文/                        # AI 输出的初稿（非权威，仅供对比学习）
│   ├── 第001章.md
│   └── ...
├── 改文库/                      # ★ 你的定稿（权威版本，后续创作只以此为准）
│   ├── 第001章.md
│   └── ...
└── 拆书/                        # 拆书报告（可选）
    └── <书名>拆书报告.md
```

**三条纪律：**
1. **`改文库/` 是唯一权威**。任何后续章节的上下文（角色状态、剧情走向、伏笔、文风）只以改文库为准。原文写得再好看也不回流。
2. **原文和改文一一对应**，文件名严格同名，便于自动配对做风格学习。
3. **维护文档不是写完再补的**，是边写边更新的。写完一章不回写维护文档 = 下一章必出矛盾。

### 长篇精细版目录（50万字以上推荐，参考oh-story工程化理念）

> **核心理念**：文件系统才是本体——设定文件就是数据库，大纲文件就是需求文档，正文文件就是代码，追踪目录就是测试日志。写第200章想查第50章的伏笔？不用翻200章正文，直接查追踪表。

```
<小说名>/
├── 设定/                          # 按主题/人物/势力拆分文件（不是一个大文件）
│   ├── 世界观/                     # 背景设定、力量体系（按主题拆文件）
│   │   ├── 核心规则.md
│   │   ├── 力量体系.md
│   │   ├── 地理与势力.md
│   │   └── 历史与传说.md
│   ├── 角色/                       # 每个人物一个文件（沈栀.md、陆衍止.md）
│   │   ├── 主角_<姓名>.md
│   │   ├── 女主_<姓名>.md
│   │   ├── 反派_<姓名>.md
│   │   └── 配角_<姓名>.md
│   └── 势力/                       # 每个势力/组织一个文件
│       ├── <天机阁>.md
│       └── <魔教>.md
├── 大纲/
│   ├── 全书大纲.md                  # 主线一句话 + 卷级划分
│   ├── 卷级大纲.md                  # 每卷三句话 + 关键节点
│   └── 细纲/                        # 每章一个章纲，与正文一一对应
│       ├── 细纲_第001章.md
│       └── 细纲_第002章.md
├── 正文/                            # 一章一个文件
│   ├── 第001章_<章名>.md
│   └── 第002章_<章名>.md
├── 追踪/                            # 专门的追踪目录（oh-story核心创新）
│   ├── 伏笔状态表.md                # 每根伏笔的埋设/提醒/回收状态
│   ├── 时间线表.md                  # 事件的绝对时间顺序
│   ├── 人物状态表.md                # 每个角色的当前状态快照
│   └── 物品追踪表.md                # 关键道具的位置/状态/功能
├── 原文/                            # AI初稿（非权威）
├── 改文库/                          # 定稿（唯一权威）
└── 笔记.md                          # 创作笔记、灵感、待办
```

**为什么要拆分文件**：
- 一个人物一个文件 = 写正文时只读本章出场角色的文件，不用读整个大文档
- 世界观按主题拆 = 本章涉及什么设定就读什么文件，上下文更精准
- 细纲一章一个文件 = 细纲和正文一一对应，不会出现"细纲写了但正文没写"
- 追踪目录独立 = 伏笔/时间线/人物状态集中管理，写新章前先查追踪表

**选择建议**：
- 30万字以下：用上面的"标准版"（5个维护文档就够）
- 30-100万字：标准版 + 角色拆分为单独文件
- 100万字以上：用"长篇精细版"（全部拆分 + 追踪目录）

## 第三部分：初始化流程（新建项目时走一遍）

按顺序执行，约 30-40 分钟：

**第 1 步：建目录**
- [ ] 按第一部分结构建好 5 个目录
- [ ] 在 `小说资料/` 下建好 5 个维护文档（可先复制模板）

**第 2 步：填骨架**
- [ ] 写全书主线一句话（**因果链形式**，不是主题词）
- [ ] 写卷级大纲（先规划 3-5 卷，每卷三句话）
- [ ] 填世界观模板的第一节（核心规则 ≤3 条，每条带代价）

**第 3 步：建人物**
- [ ] 主角人设卡填完整（重点：欲望 / 恐惧 / 真缺陷 / 弧光）
- [ ] 2-3 个核心配角人设卡（重点：各自的目标 + 与主角的关系）
- [ ] 角色索引表建好

**第 4 步：埋线**
- [ ] 列出 5-10 个重要伏笔，标注埋设位置和计划回收位置
- [ ] 填入伏笔追踪表

**第 5 步：定调**
- [ ] 确定主文风（占 70%）+ 1-2 个辅助元素（各 15%）
- [ ] 确认目标平台与读者画像
- [ ] 把主文风、禁用词、通用负向约束写进一个"文风备忘"，每次写正文时随提示词一起注入

**第 6 步：试跑**
- [ ] 按 SOP 写前三章
- [ ] 走一遍完整循环（细纲 → 注入 → 初稿 → 四轮去味 → 人工定稿 → 回写维护文档）
- [ ] 确认这套流程你跑得下来，再开始稳定更新

## 第四部分：读写纪律（每章强制执行）

### 写作前：强制读取清单

```
□ 小说资料/人物库.md       → 本章出场角色的"当前状态"
□ 小说资料/世界观.md        → 本章涉及的设定条目 + 已揭示/未揭示边界
□ 小说资料/章节摘要.md      → 最近 3-5 章（不用读全文）
□ 小说资料/伏笔追踪表.md    → 全部未回收伏笔（本章要不要提醒/回收？）
□ 小说资料/时间线表.md      → 本章的时间节点
□ 大纲/章节细纲.md          → 本章细纲
□ 改文库/第N-1章.md         → 上一章结尾（500-800字）
```

### 上下文卡（每章写作前生成，只读这一张卡）

> **核心思想**：不要分别读5个文档，把所有关键信息浓缩成一张"上下文卡"，下一章只读这张卡。几百章也不会崩人设、忘伏笔。

**上下文卡模板（每章一张，放在 `上下文卡/第N章.md`）：**

```markdown
# 第 N 章上下文卡

## 一、承接（上一章结尾）
> 直接复制上一章最后300-500字，确保衔接自然
[粘贴上一章结尾]

## 二、本章细纲
> 本章要写什么，1-3句话
[本章细纲]

## 三、出场角色当前状态
| 角色 | 当前位置 | 身体状态 | 情绪状态 | 已知信息 | 目标 |
|------|---------|---------|---------|---------|------|
| 主角 | | | | | |
| 配角A | | | | | |

## 四、本章涉及的世界观设定
> 只列本章会用到的设定，不要列全部
- [设定1]：[一句话说明]
- [设定2]：[一句话说明]

## 五、未回收伏笔（本章可能用到的）
| 伏笔内容 | 埋设章节 | 类型 | 本章计划 |
|---------|---------|------|---------|
| | | | 提醒/回收/暂不处理 |

## 六、时间线
- 当前时间：[年月日/时辰]
- 距上一章：[过了多久]
- 本章时间跨度：[多久]

## 七、本章章末钩子
> 写完本章后填写，作为下一章上下文卡的"承接"
[本章章末钩子]
```

**使用流程：**
1. **写作前**：根据维护文档生成本章上下文卡（5分钟）
2. **写作中**：只读上下文卡，不翻其他文档
3. **写作后**：更新维护文档，然后生成下一章的上下文卡

**为什么用上下文卡**：
- 避免AI"全知全能"——只给它本章需要的信息，不给它全部设定
- 提高效率——不用每次读5个文档，只读一张卡
- 防止信息泄露——上下文卡中的"已知信息"栏严格控制角色知道什么
- 长篇不崩——几百章后，每张上下文卡都是准确的"当前状态快照"

### 写作后：强制更新清单

```
□ 小说资料/章节摘要.md      → 追加本章摘要条目
□ 小说资料/人物库.md        → 更新角色当前状态；新增角色建档
□ 小说资料/世界观.md        → 新增设定；记入变更日志
□ 小说资料/伏笔追踪表.md    → 新增伏笔；标记已回收
□ 小说资料/时间线表.md      → 追加本章事件的绝对时间
```

> **为什么这么严**：AI 没有跨章记忆。你不回写，下一次注入上下文时就没有这条事实，AI 就会"发明"一个合理但错误的替代。**回写维护文档 = 给 AI 装记忆。**

## 第五部分：一致性审计

### 小审计（每 5 章）

- [ ] 人物：名字/别名/外貌/能力等级/伤势有没有前后一致
- [ ] 关系：关系变化有没有触发事件（不能"上章是敌人这章突然友好"）
- [ ] 物品：关键道具的位置/状态/功能/数量
- [ ] 伏笔：新埋的登记了吗？该收的收了吗？
- [ ] 配角：有没有角色凭空消失（出场后就没再提）

**执行方式**：用 `11-prompt-library.md` 的 **G4 一致性比对**提示词，把新 5 章和事实库丢给 AI 做初筛，人工终审。

### 大审计（每卷末）

- [ ] 本卷核心冲突是否解决（或推进到新阶段）
- [ ] 本卷规划的伏笔是否回收（或有合理的延迟理由）
- [ ] 主角是否有可感知的成长/变化
- [ ] 卷末高潮是否足够精彩、卷末钩子是否够强
- [ ] 全书设定有没有前后矛盾（逐条对世界观文档）
- [ ] 时间线有没有冲突（做一次算术验证）
- [ ] 章节摘要和正文是否匹配
- [ ] 下一卷大纲是否需要调整

### 完本终审

- [ ] 主线完整，核心冲突最终解决
- [ ] 所有重要伏笔都已回收或明确废弃
- [ ] 主角弧光完整（起点→转折→终点）
- [ ] 主要配角结局都有交代
- [ ] 世界观的核心矛盾有了答案
- [ ] 结尾有余韵（不仓促，也不拖沓）

## 第六部分：命名规范与常见问题

### 命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| 章节文件 | `第NNN章.md`（三位补零，便于排序） | `第007章.md` |
| 原文/改文 | 严格同名，分别放在 `原文/` 和 `改文库/` | `原文/第007章.md`、`改文库/第007章.md` |
| 拆书报告 | `<书名>拆书报告.md` | `凡人修仙传拆书报告.md` |
| 分卷细纲 | `第N卷细纲.md` | `第1卷细纲.md` |

### 常见问题

**Q：维护文档太琐碎，每章都要更新很累怎么办？**
A：用 AI 代劳。写完正文后跑一次 `11-prompt-library.md` 的 I1（章节摘要生成），人工核对 1 分钟即可。人物库只更新"当前状态"栏，不必重填全表。

**Q：写到一半发现前期设定要改怎么办？**
A：改设定可以，但要三步走：① 在世界观文档的"变更日志"记一笔（改了什么、为什么、影响哪些章）；② 回头检查受影响的已发布章节是否需要修文；③ 确认后续大纲是否需要同步调整。**不要只在正文里悄悄改。**

**Q：改文库和原文差异很大，还要维护原文吗？**
A：要。原文的唯一价值是"拿来和改文对比学习"。但**原文不回流**——不要因为原文某句写得"更好看"就沿用，你没采纳的写法恰恰是要规避的。

**Q：第三人称多视角的作品怎么办？**
A：人物库的"当前状态"要按视角人物分别记录（尤其"该角色知道什么信息"这一栏），否则多视角作品最容易出"角色知道了不该知道的事"。可另建一张"信息知情表"记录每个角色掌握的关键信息。

**Q：写到 50 万字后维护文档太长，读不完怎么办？**
A：分段维护。人物库按"当前活跃/已退场"分区；章节摘要只保留下最近 30 章在文件顶部，更早的归档到 `章节摘要-归档.md`；伏笔表只保留未回收的 + 最近 20 章已回收的。

### 脚本2：wordcount.sh — 章节字数统计

```bash
#!/bin/bash
# wordcount.sh - 统计所有章节字数
BOOK_DIR="${1:-.}"
TARGET="${2:-2500}"  # 默认目标2500字/章（番茄最佳）

echo "📊 章节字数统计 (目标: ${TARGET} 字)"
echo "================================"
total=0
count=0
for chapter in "${BOOK_DIR}/改文库"/*.md; do
  [ -f "$chapter" ] || continue
  filename=$(basename "$chapter")
  # 统计中文字符数（去掉markdown标记和空白）
  char_count=$(sed 's/#//g;s/\*//g;s/[[:space:]]//g' "$chapter" | wc -m)
  total=$((total + char_count))
  count=$((count + 1))
  if [ "$char_count" -lt "$TARGET" ]; then
    echo "⚠️  ${filename}: ${char_count} 字 (不足目标)"
  else
    echo "✅  ${filename}: ${char_count} 字"
  fi
done
echo "================================"
if [ "$count" -gt 0 ]; then
  echo "📖 总计: ${total} 字 | 平均: $((total / count)) 字/章 | 共 ${count} 章"
fi
```

**使用方法**：`bash wordcount.sh "小说目录" 2500`

### 脚本3：chapter_check.sh — 章节完整性检查

```bash
#!/bin/bash
# chapter_check.sh - 检查细纲和正文是否一一对应
BOOK_DIR="${1:-.}"

echo "🔍 章节完整性检查"
echo "================================"

# 检查细纲
outline_count=$(ls "${BOOK_DIR}/大纲/细纲/"*.md 2>/dev/null | wc -l)
# 检查正文
draft_count=$(ls "${BOOK_DIR}/原文/"*.md 2>/dev/null | wc -l)
# 检查改文
final_count=$(ls "${BOOK_DIR}/改文库/"*.md 2>/dev/null | wc -l)

echo "📋 细纲: ${outline_count} 章"
echo "📝 原文: ${draft_count} 章"
echo "✅ 改文: ${final_count} 章"
echo ""

# 检查是否有细纲但没正文的章节
if [ "$outline_count" -gt "$final_count" ]; then
  echo "⚠️  有 $((outline_count - final_count)) 章细纲还没写成正文"
fi

# 检查是否有正文但没细纲的章节（违反门禁规则）
if [ "$final_count" -gt "$outline_count" ]; then
  echo "🚨 有 $((final_count - outline_count)) 章正文没有对应细纲！（违反'缺细纲不许写正文'门禁）"
fi

echo ""
echo "📊 完成率: 细纲${outline_count} → 原文${draft_count} → 改文${final_count}"
```

**使用方法**：`bash chapter_check.sh "小说目录"`

### 脚本使用建议

- **init_novel.sh**：开新书时跑一次，自动建好完整目录结构
- **wordcount.sh**：每写完一章跑一次，确保字数达标（番茄2200-2800最佳）
- **chapter_check.sh**：每周跑一次，检查细纲和正文是否一一对应，防止跳步
- 这些脚本是"效率放大器"，不是"创作替代品"——创造力还是要靠人
